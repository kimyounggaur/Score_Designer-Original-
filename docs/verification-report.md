# MXL Studio09 검증 보고서

검증일: 2026-09-03  
환경: Windows, Node.js 24.18.0, 설치된 Chrome

## 자동 검증

| 구분 | 결과 |
|---|---|
| Vitest 단위 테스트 | 8개 파일, 84개 통과 |
| Playwright 전체 | 84개 중 80개 통과, 4개 제외, 5.5분 |
| 21개 패널 매트릭스 | 21개 패널과 히스토리 흐름 통과 |
| 접근성 | 빈 화면·악보·공유 모달·세션 모달에서 axe serious/critical 0 |
| 모바일 | Pixel 5 프로젝트의 `@ux` 흐름 통과 |
| 문서 브라우저 테스트 | 기존 코어 HTML 테스트 3종 PASS |

제외 4개 중 하나는 모바일 화면에 적용되지 않는 데스크톱 패널 폭 검사입니다. 나머지 세 개는 Linux CI가 정본인 f01·f04·f09 시각 회귀입니다. 테스트와 생성 워크플로는 준비됐으며 첫 기준 이미지는 GitHub `Nightly Full Test`를 `update_snapshots=true`로 실행해 만든 아티팩트를 검토한 뒤 반영합니다.

## 성능 측정

21개 패널을 처음부터 모두 마운트하던 기준은 `.app-root` 표시까지 4,326/4,418/3,785ms, 평균 4,176ms였습니다. 방문 패널 지연 마운트와 JSX 전용 Babel 설정 뒤에는 1,920/1,873/2,731ms, 평균 2,175ms로 약 48% 줄었습니다. 네트워크와 실행 중인 프로세스의 영향을 받는 로컬 비교값이며 서비스 수준 보장치는 아닙니다.

f09에서 12회 조옮김한 13개 기록의 고유 UTF-16 문자열 추정치는 16,648,068바이트(15.88MiB)였습니다. 문자열 스냅샷의 최종 CPU 측정은 316/358/319ms였습니다. JS heap 수치는 native DOM 메모리를 포함하지 않고 GC 변동도 커서 총 메모리 절감률로 사용하지 않았습니다.

## 문서와 화면 검증

설명서용 화면 11장을 촬영했습니다. 데스크톱 10장은 1280×800, 모바일 한 장은 390×844입니다. 사용자 설명서 10쪽, 퀵스타트 4쪽, 업데이트 안내 3쪽의 PDF 전 페이지를 이미지로 렌더해 잘림·겹침·빈 페이지가 없는지 확인했고 SVG도 같은 PDF에서 다시 생성했습니다. 문서 키워드의 변경 전 문맥과 처리 결과는 [매뉴얼 기능 점검](manual-audit.md)에 있습니다.

## 구현 범위와 남은 외부 검증

기준 설계의 Phase 0~8 로컬 구현과 문서 동기화를 마쳤습니다. 선택 Phase 9의 주석·청음·난이도·운지·QR·AI·클라우드 기능은 현재 범위에 포함되지 않습니다. D.C./D.S./Fine/코다 재생 이동은 Phase B에서 한 번 점프 규칙으로 구현했고, 중첩·복수 점프는 지원하지 않습니다.

GitHub Pages 대상은 `https://kimyounggaur.github.io/Score_Designer-Original-/mxl-studio.html`입니다. 푸시 후 Pages 배포와 Linux CI를 실행하고, Linux 기준 이미지 3장을 반영해야 P7-2의 두 번째 완료 조건이 충족됩니다.

## 2026-11-09 Studio10 Phase A 재검증

환경: Linux, Node.js 22.23.4, Google Chrome for Testing 153 (헤드리스). 작업 환경에서 외부 CDN 접속이 막혀 React·OSMD·Tone·JSZip 등 같은 버전·같은 바이트의 라이브러리 파일을 로컬 HTTPS 미러로 제공했습니다(SRI 일치 확인).

| 구분 | 결과 |
|---|---|
| Vitest 단위 테스트 | 10개 파일, 142개 통과 (pitch-core·measure-core 추가) |
| Playwright 전체 | 111개 중 107개 통과(chromium 100, mobile 7), 4개 제외, 6.1분 |
| 접근성 | 빈 화면·악보·공유 모달·세션 모달에서 axe serious/critical 0 |
| 변환 정확도 | 음역대·음자리표·마디별 조바꿈·특정 조·카포·화성 쌓기·자리바꿈·Ossia의 철자·방향·마디 번호 E2E, 적용 대상 토글, 12개 조 ZIP |

제외 4개는 이전과 같습니다(모바일의 데스크톱 패널 폭 검사 1개, Linux 기준 이미지가 없는 시각 회귀 3개).

설명서 10쪽과 퀵스타트 4쪽 PDF를 `npm run docs:build`로 다시 만들고 전 페이지를 이미지로 렌더해 잘림·겹침·빈 페이지가 없음을 확인했습니다. Linux에는 Malgun Gothic이 없어 한글은 Noto Sans CJK로 표시됩니다. 내용이 바뀌지 않은 업데이트 안내 PDF·SVG는 다시 만들지 않았습니다. 설명서 화면 이미지는 Studio09 화면 그대로입니다.

## 2026-11-10 Studio10 Phase A2 재검증

환경: Linux, Node.js 22.23.4, Google Chrome for Testing 153 (헤드리스), Phase A와 같은 로컬 HTTPS 미러(SRI 일치). 근거는 2026-11-09 외부 검수 보고서(B01~B10·C01~C18)와 그 소스 대조이며, 수정 범위는 `MXL-Studio10-PhaseA2-검수대응-바이브코딩-프롬프트.md`의 A2-1~A2-11입니다.

| 구분 | 결과 |
|---|---|
| Vitest 단위 테스트 | 11개 파일, 185개 통과 (numbering-core 추가, chord-tools·roman·transpose·session-store·playback 확장) |
| Playwright 전체 | 154개 중 150개 통과(chromium 141, mobile 9), 4개 제외, 8.6분 |
| 접근성 | 빈 화면·악보·공유 모달·세션 모달·반복 기호 경고 장면에서 axe serious/critical 0, 음자리표·템포 프리셋·눈금 키보드 조작 |
| 데이터 보존 | 현재 파일 범위 로마 숫자 삽입이 다른 파일을 덮지 않음(B01), 파트 ID가 없는 파일은 건너뜀(B02), 템포 변경이 duration을 바꾸지 않음(B03), 다른 패널 뒤에도 원본 가사 복원(B04), 히스토리 지우기 뒤 되돌리기(B07), 저장 실패를 ok:false와 이유로 전달하고 구세션 키를 성공 시에만 삭제(C11·C12) |
| 분석·변환 정확도 | 3음 미만 코드 미확정·박 단위 수직 분석·못갖춘마디 0(C01·C02·C15·C18), 이조 악기 실음·마디별 조표·IAC(C09·C10), 보표별 조표·온음계 음정(C05·C06), 통계 마디·단조·실제 철자(B09·C08·N6) |

바뀐 동작 요약: 템포 'duration 비례 변환' 제거(D1), 숫자 악보 생성 가사 표식과 원본 백업(D3), 옥타브 점(D4), 히스토리 기준점(D6), Ossia는 PNG·SVG 포함·MXL 제외 알림(D7), IAC(D8), 코드 확정 기준(D9·D10), 온음계 음정과 완전음정 칩(D11), 한글 오류문(D12). 추가 발견으로 XML 선언이 없는 MusicXML이 그려지지 않던 문제(OSMD가 문자열을 URL로 해석)를 고쳤습니다.

설명서 10쪽과 퀵스타트 4쪽을 `npm run docs:build`로 다시 만들고 전 페이지를 이미지로 확인했습니다(Linux라 한글은 Noto Sans CJK). 내용이 바뀌지 않은 업데이트 안내 PDF·SVG는 원래 파일을 유지했습니다. 설명서 화면 이미지는 Studio09 화면 그대로입니다.
